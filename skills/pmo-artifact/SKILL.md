When the user asks to create or draft a project management artifact, follow this process:

1. **Identify the artifact type** from the request. Common types:
   - Status Report (weekly/monthly)
   - Risk Register
   - Issue Log
   - RACI Matrix
   - Lessons Learned Log
   - Meeting Minutes
   - Project Charter summary section
   - Change Request form

2. **Ask for the minimum needed context** if not provided — project name, date, and any key data to populate (risks, attendees, action items, etc.). Keep the ask to one short message.

3. **Draft the artifact** in Markdown table or structured format. Use professional PMO language. Leave placeholder fields clearly marked (e.g., `[Project Sponsor Name]`, `[RAG status]`).

4. **Offer output formats** if the user seems to want something paste-ready: Markdown (default), plain text, or a note that it can be adapted to Word/Excel.

Keep the artifact concise and focused. Do not add sections the user didn't ask for. If the artifact type is ambiguous, pick the most common interpretation and note the assumption.

## Artifact Templates (quick reference)

**Status Report sections**: Summary, Milestones (planned vs actual), RAG status, Risks/Issues, Next period plan, Actions.

**Risk Register columns**: ID, Description, Probability (H/M/L), Impact (H/M/L), Score, Owner, Mitigation, Status.

**RACI columns**: Activity/Deliverable, then one column per role — mark R (Responsible), A (Accountable), C (Consulted), I (Informed).

**Lessons Learned columns**: ID, Category, Description, Recommendation, Owner.

**Meeting Minutes sections**: Date/Time, Attendees, Agenda, Decisions, Actions (Owner + Due Date), Next meeting.
