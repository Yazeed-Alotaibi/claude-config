Design section 3: Validation and rollout

  Because AGENTS.md is behavioral configuration rather than executable code, validation should combine static checks with fresh-session scenarios.

  #### Static checks

  - Valid Markdown with no placeholders or incomplete clauses.
  - Exact Codex pull and Codex push triggers and commands preserved.
  - git add -A appears only inside the Codex push exception.
  - No contradictory commit, authority, or completion rules.
  - No duplicated verification requirements.
  - No embedded secrets, private data, or machine-specific credentials.
  - Materially smaller than the current file.
  - Existing unrelated .Codex changes remain untouched.

  #### Acceptance criteria

  - Routine work remains autonomous and concise.
  - Protected actions never rely on inferred authority.
  - Destructive local actions receive the same protection as external writes.
  - Material work receives proportional planning and review.
  - No secret or unexpected file is knowingly committed or pushed.
  - Completion is supported by evidence from after the final relevant change.
  - Permission-gated commits behave correctly at task, session, and repository scope.
  - No scenario causes repetitive classification output or unnecessary checkpoints.

  #### Rollout

  - Record the existing .Codex Git state before editing.
  - Replace only .Codex\AGENTS.md; leave other configuration files untouched.
  - Review the final diff and rerun the static checks.
  - Start a fresh Codex session for behavioral validation because global instructions are loaded at session startup.
  - Leave the .Codex change uncommitted for the literal Codex push workflow.
  - Refine the contract only in response to observed failures, avoiding speculative additions.
